# SKTJF v1

SKTJF means **Shit school, Kosen Timetable JSON Format**. It is a distribution format for school-provided schedules, not a personal backup or SKTTP payload. The normative shape is [sktjf-v1.schema.json](../schema/sktjf-v1.schema.json); additional semantic rules are implemented by the validator. Schema validation alone does not establish that a timetable was reviewed or that every source cell was covered.

One JSON document describes one school, academic year, term and class. Undergraduate class IDs are `1-1` to `1-4` and `2M` through `5B` using the M/E/I/B course codes. `AC-` followed by uppercase letters or digits is reserved for non-colliding graduate-course IDs; IDs must correspond to actual published classes. Revision is `YYYY.S.N` or `YYYY.F.N`, matching academic year and term; a revision must not be replaced after publication.

`periods` declares numbered start/end times in local school time. `lessons` is a list rather than a map by slot: multiple lessons may occupy the same weekday and period, including overlapping or different student conditions. `WEEKLY`, `A` and `B` describe the cycle; `conditions.all` requires every attribute and `conditions.none` excludes any listed attribute. Empty lists mean no restriction. Attribute IDs are stable identifiers such as `DD` and `INTERNATIONAL`; they do not imply a choice of elective subjects. Each lesson has a stable ID, explicit kind and references to source documents and pages. `MAKEUP` uses subject `補講`, `EXTENSION` uses `延長枠`; note ※3 is not a lesson.

`slotCoverage` explicitly marks each reviewed slot as `PRESENT`, `EMPTY`, or `EXCLUDED`. An excluded slot is intentionally outside distribution, for example ※3, and is distinct from a confirmed empty slot. `containsExcluded` also marks a present slot that contains excluded content alongside distributed lessons. Neither state authorizes deleting an individual student's local lesson. Every present slot must have at least one lesson, and every lesson must have a matching present slot.

`calendar` assigns each date a day type, optional reference weekday and A/B type, and an optional event with its original name. An event with no mapped existing kind uses `OTHER`; exam dates are attributes, not exam subjects or exam schedules. A null day type represents an explicitly undetermined state, not a holiday. The weekday override refers to the timetable to apply, not the actual weekday of the date.

`sources` records a document name and SHA-256, plus an optional HTTPS URL. References identify source ID and one-based page; source PDF bytes are not embedded. SHA-256 verifies source identity, not correctness or authenticity. Validators must reject unsupported versions, invalid references, duplicate identifiers/dates, inconsistent revision/date/period values and contradictory conditions. Publication also requires independently verifying review status, source coverage, target class completeness and all unresolved warnings; these cannot be established from a schema-valid document alone.
